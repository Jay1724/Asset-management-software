Why it's different

Same core problem every mine site spreadsheet is trying to solve — asset value over time — handled properly.

Depreciation

Three methods, one engine

Straight-line, declining-balance, and units-of-production — the last one priced per hour or per tonne, not per calendar year, which is what actually matches how mining equipment wears out.

Security

Tenant isolation enforced by the database

Row-Level Security policies key every table on the signed-in user's tenant. A bug in a form or a query can't leak another tenant's data — Postgres itself refuses the row.

Branding

White-label per tenant

Logo, colors, and name resolved from the signed-in tenant and applied across the app — the login screen, the nav, every stat card.

Audit

Immutable valuation ledger

Every depreciation run and manual appreciation/adjustment is appended to a permanent history — never edited, never deleted. The number banks and auditors want to see.

Access

Role-based, not all-or-nothing

Admin, Site Manager, Technician, and Auditor each see the platform differently — write access to sites and assets is gated by role, not just by login.

Deploy

No server to run

The whole frontend is one HTML file talking directly to a hosted Postgres database. No server to run, no infrastructure to maintain.

Built around who's actually using it

Four roles, each scoped to what they need to do on site.

Admin
Full control — sites, categories, assets, manual valuation adjustments.
Site Manager
Creates and updates assets, runs depreciation recalculations.
Technician
Logs usage (hours/tonnage) that feeds the depreciation engine.
Auditor
Read access to every asset and its full valuation history.

How it works

Ten minutes, no server to stand up.

  1. Create a free Supabase project — a hosted Postgres database with built-in auth and Row-Level Security.
  2. Run one SQL script — supabase/schema.sql sets up every table, security policy, and the depreciation engine itself (as database functions).
  3. Add your first user and some assets — through the Supabase dashboard, or paste in supabase/seed-demo-assets.sql for sample data.
  4. Sign in — open app.html, point it at your project, and it's a real multi-user platform.
